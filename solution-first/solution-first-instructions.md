## The golf-ball rule

Start from a claim, fact, assertion, or joke already in the docs. Ask what world problem it could solve. Do not write a problem list first. If someone later recognizes the claim as their missing piece, that is a hit. If the problem has to be invented to make the claim look useful, throw the pairing out.

## Scope

Built for about 1.5 to 2 TB of Drive, four years of science writing, plus junk mail that must be parked, not deleted.

Drive stays read-only. Do not write into Drive.

## Six steps

### 1. Gather

Pull every claim, fact, assertion, and joke. Tag speaker: Phil, AI, or pasted. Tag type. Keep junk mail in a separate register with the same IDs so it can be found again.

Output: claim cards, a junk-mail register, no deletions.

Do not pre-filter by topic. Do not clean jokes out. Do not write into Drive.

### 2. Rank

Score each card on specificity (a number, a named mechanism, a testable sentence) and recurrence (same idea in more than one doc or year).

Output: a ranked deck. High-specificity repeats rise first.

Do not rank by how fashionable the topic is.

### 3. Ask

For each top card: what problem does this already solve if someone else has it? Write the problem as a question that a stranger could recognize.

Output: claim-to-problem pairs with confidence.

Do not start from UN goals or a canned crisis list.

### 4. Anchor

Force the first full pass through four keywords already in the pile: Hubble's constant (End of the Universe), Planck's limit, algorithms, IGLI (Glory Road / E74).

Output: four seed clusters, not a complete inventory.

Do not treat anchors as the only allowed topics.

### 5. Map

After a few hundred cards exist, embed them and look at the white space between clusters. Empty space is a candidate for an unstated problem.

Output: a cluster map plus a short list of gaps.

Do not embed 2 TB on day one. Science pile first.

### 6. Match

Hold the claim still and hunt for a problem that fits it. Prototype on a small slice before any scale run.

Output: a canvas, then a second slice.

Do not automate matching until a human has rejected a few false pairs.

## How to score a pairing

Confidence is about the pairing, not about the physics.

- High: the document is already doing this work.
- Medium: one step out from the wording.
- Low: a jump the document does not make.

A pairing that is not written in any one doc is speculative. Confidence stays low until a third card lands in the same gap.

The method fails when the ask reaches for a canned crisis (climate, alignment, education) that the claim did not ask to enter. Stay greedy for the document's own question.
